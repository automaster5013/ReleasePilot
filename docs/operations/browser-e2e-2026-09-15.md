# 공개 데모 브라우저 검증 (2026-09-15)

## 결과: 실패, 후속 흐름 미검증

대상은 `https://releasepilot.kr/`, 브라우저는 Codex 내장 브라우저다. 운영 릴리스 mutation은 실행하지 않았다.

- 초기 화면: 제목, 릴리스 snapshot, 판정 근거와 감사/세션 영역이 렌더링됐다.
- 로그인 전 안전성: Promote, Pause, Resume, Abort 및 릴리스 불러오기/새로고침 버튼이 비활성으로 표시됐다. Promote의 enabled 값도 false였다.
- 데모 진입: `읽기 전용 데모` 클릭 후에도 DEMO SNAPSHOT과 빈 최근 릴리스 목록이 유지됐다. 새로고침 후 클릭에서도 같은 증상을 확인했다.
- 콘솔: 두 문서 로드에서 `Minified React error #412`가 기록됐다. 오류 위치는 `/_next/static/chunks/0cegfsgm6lvdz.js`다. 이 오류와 로그인 미반응의 인과관계 및 서버/브라우저 측 원인은 아직 확정하지 않았다.
- VIEWER 로그인, 실제 릴리스 조회/선택, 감사 이력, 세션 유지와 로그인 후 권한은 진입 실패 때문에 미검증이다. 로그인 전 비활성 버튼만으로 VIEWER 권한 검증 성공을 판단하지 않는다.

직전 점검의 DNS 오류는 이번 연결에서 재현되지 않았다. 이전 HTTP 헬스 점검 성공은 브라우저 상호작용 성공을 의미하지 않는다.

## 다음 조치

일반 브라우저에서도 동일 증상인지 확인하고 React 클라이언트 초기화/이벤트 연결, 정적 asset 일치와 session API 응답을 조사한다. 원인에 맞는 수정 후 데모 진입부터 다시 실행한다. 이번 결과는 E2E 통과 또는 전체 완료 기록으로 사용하지 않는다.

## v0.49.0 수정 후 재검증

기존 CSP는 script-src 없이 default-src 'self'로 인라인 bootstrap을 차단했다. 요청마다 32-byte 난수 nonce를 생성하고 Next.js 렌더링 요청과 응답에 같은 정책을 적용했다. 정적 CSP를 제거하고 layout을 동적 렌더링으로 전환했다. production script-src에는 unsafe-inline/unsafe-eval을 추가하지 않았다.

- 웹 테스트 32개(보안 정책 회귀 3개 포함), lint, typecheck, production build 통과.
- [전체 CI](https://github.com/automaster5013/ReleasePilot/actions/runs/34936437042)와 [이미지 배포](https://github.com/automaster5013/ReleasePilot/actions/runs/34936439575) 성공.
- 배포 revision `7210ec46a859239e983fb987501af83623fc4487`에 Argo CD Synced/Healthy. 세 Rollout 모두 Healthy, ready/updated/available 각각 2.
- HTTPS HTML 두 요청에서 각 9개 script의 nonce가 CSP와 일치하며, 두 요청의 nonce가 서로 다르고 Cache-Control이 private, no-store임을 확인했다.
- 내장 브라우저에서 데모 버튼 클릭 후 DEMO · VIEW ONLY로 전환되고 최근 릴리스 새로고침이 활성화됐다. React 오류 #412 및 warning/error 로그는 재현되지 않았다.
- 로그인 후 Promote/Pause/Resume/Abort의 enabled 값은 모두 false였다. 공유 데모 세션 관리 차단 안내가 표시됐다.
- 페이지 새로고침 뒤 비동기 세션 복원이 완료되면 릴리스 새로고침과 공유 데모 안내가 다시 표시됐다. 단, 상단 연결 문구는 DEMO SNAPSHOT으로 남는 별도 표시 문제가 관찰됐다.
- 최근 릴리스 새로고침은 오류 없이 빈 목록을 유지했다. 조회 가능한 실제 릴리스가 없어 상세 선택·실제 판정/감사 이력 E2E는 여전히 미검증이다. 조직 역할별 SSO도 이번 범위에 포함하지 않았다.

데모 진입 장애 수정은 완료했지만, 전체 E2E 통과를 선언하지 않는다. 후속 검증에는 격리된 테스트 릴리스/계정과 일반 브라우저 연결이 필요하다. 운영 데이터를 검증 목적으로 새로 생성하거나 변경하지 않았다.

## v0.50.0 세션 복원 표시 수정

상단 문구를 클릭 시 저장한 값 대신 현재 인증된 SessionUser와 선택된 릴리스/stream 상태에서 계산하도록 변경했다. 인증 전/세션 종료는 DEMO SNAPSHOT, 데모는 DEMO · VIEW ONLY, 일반 조직 세션은 SIGNED IN이다. LIVE/RECONNECTING은 로그인과 릴리스 선택이 모두 있는 경우에만 유지한다. 권한 판정에는 이 표시 문구를 사용하지 않는다.

- 웹 테스트 34개, lint, typecheck, production build 통과. 복원·세션 종료·stream 표시 회귀 테스트 2개 추가.
- [전체 CI](https://github.com/automaster5013/ReleasePilot/actions/runs/34937065079)와 [이미지 배포](https://github.com/automaster5013/ReleasePilot/actions/runs/34937068676) 성공.
- 배포 revision `e07173aced4f9477299e39547a9320d0d1dd398d`에 Argo CD Synced/Healthy. 세 Rollout Healthy, ready/updated/available 각각 2.
- 내장 브라우저에서 데모 로그인 후 페이지를 새로고침했다. 세션 복원 완료 후 navigation이 DEMO · VIEW ONLY를 포함하고 DEMO SNAPSHOT을 포함하지 않는 것을 확인했다.
- 복원 후 최근 릴리스 새로고침은 활성, Promote/Pause/Resume/Abort는 모두 비활성, 공유 데모 세션 관리 차단 안내는 표시됐다. 콘솔 error/warn 로그는 없었다.

세션 복원 표시 수정은 완료했다. 빈 최근 릴리스 목록으로 인한 실제 상세/감사 이력 E2E 제한은 그대로 남는다.
